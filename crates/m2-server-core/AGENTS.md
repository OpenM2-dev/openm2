# m2-server-core and m2-server — rules for agents

openm2's own server. `m2-server-core` is its brain: connections' messages, the time, storage's answers and the edge's checks of providers' sign-ins come in, effects go out (send a message, close a connection, ask storage, check a sign-in, report an event). **No I/O, no clock, no threads.** `m2-server` is the edges around it and the `openm2-server` binary. What the server does: `docs/specs/server/session.md` and `world.md`; what it stores: `storage.md`; what it reads: `content.md`; running it: `docs/server.md`.

## Layout
- `m2-server-core/src/server/mod.rs`: `Server::step(now, input) -> Vec<Effect>`. Inputs: `Accepted`, `Message`, `Closed`, `Stored`, `SignInChecked`, `Tick`, `Shutdown`. Effects: `Send`, `Close`, `Store`, `CheckSignIn`, `Event`. Each connection's `Stage` (hello, login, checking, ticket, joining, select, loading, game), its sign-in nonce, the tickets, failed-login counts, ticks (pings, timeouts, sign-in deadlines, saves), closing.
  - `hello.rs` (versions: Welcome or Refused), `auth.rs` (providers' sign-ins, the only way in: the options and nonce, what the core checks itself, the edge's answer, then the identity's account through storage; 32-byte tickets, throttling by address), `select.rs` (the list, creating with the first character's empire, selecting), `world.rs` (entering, players seeing each other, moves, chat, commands), `mobs.rs` (the content's monsters and NPCs: placing them, groups waking and sleeping, strolls, fighting back, chasing, giving up, dying and coming back, what players see of them; each monster's next step on one timer), `combat.rs` (targets, players' hits and their checks, the damage rule, players dying and restarting), `points.rs` (Points, then PointsChanged with what changed; maxima, experience and levels, regeneration), `items.rs` (the bag and worn items, using and moving them, gear with what skills raise, quickslots, starting items), `ground.rs` (items on the ground: dropping, picking up, owners and expiry, monsters' drops), `shops.rs` (talking to NPCs, their shops, buying, selling), `skills.rs` (the skill group, skill points, using skills on oneself or another player, their hits and what they raise for a while), `effects.rs` (what skills do besides: the points that change how hits and bites land, states on monsters, pushes, skills that stay on, hiding, Affects), `whispers.rs` (a line to one player in the game by name, never kept), `friends.rs` (friend requests, answers, ending a friendship, friends coming and going, friendships' writes), `mounts.rs` (players' mounts: calling, getting on and off, riding speeds, stamina and food, stables' training, what riding lets a rider do; the following itself is in `mobs.rs`), `upgrades.rs` (items upgraded at a smith or with a scroll: the offer, then the upgrade checked again, its costs and chance), `walk.rs` (walk times, positions along a walk, the 72 directions monsters walk in, as degrees on the wire), `grid.rs` (who is where, in cells as wide as the view radius).
- `m2-server-core/src/store.rs`: `StoreRequest` and `StoreAnswer`, the only way to storage. `sign_in.rs`: `SignIn`, `Identity` and `SignInRefusal`, what the core asks the edge to check of a provider's sign-in. `config.rs`: the rules an operator may change, with their defaults. `time.rs`: `Millis`, `ConnId`.
- `m2-server-core/tests/`: `scenarios.rs`, `sign_in.rs`, `world.rs`, `combat.rs`, `items.rs`, `shops.rs`, `skills.rs`, `skill_effects.rs`, `whispers.rs`, `friends.rs`, `mounts.rs` and `upgrades.rs` (snapshots in `snapshots/`), `random_sessions.rs` (property tests, with and without monsters, fights, items, shops and skills), `support/` (a harness with a store in memory that answers at once or holds saves, friendships' writes or loads back, and holds sign-in checks for the test to answer; `Harness::with_content` logs in detail, `quiet_ticks` leaves idle ticks out).
- `m2-server/src/runner.rs`: `runtime`, `start`, the listeners, a TLS handshake task per new connection (a timeout, a cap in all and per address), a reader and writer task per connection, the core task. `tls.rs`: `Identity`, the certificate (the operator's PEM files, or a self-signed one made into the data folder or for one run) and the rustls configuration. `oidc.rs`: the providers file, discovery, the code exchange, the ID token's checks and the keys' cache. `store/`: `Store` with `MemoryStore` and `PgStore` (SQL, the migration runner, `migrations/*.sql`). `telemetry.rs`: logging, OTLP export, the metrics. `content.rs`: a content folder from disk. `main.rs`: the CLI (`serve`, which needs `--providers`; `migrate`, `content check`, `tls key`).
- `m2-server/tests/`: `clients.rs` (the running server with real clients, `m2-core` and `m2-net`, a provider's sign-in among them), `oidc.rs` (providers' sign-ins against the fake provider), `tls.rs` (clients that do not finish a TLS handshake with `openm2/1`), `storage.rs` (storage's rules on both stores, identities too, a restart on Postgres), `support/` (the server in the test's process with a certificate made at start, a Postgres schema per test; `issuer.rs`, a fake OpenID Connect provider and browser, which `m2-cli`'s tests include too).

## Rules
- **The core is deterministic**, as `m2-core` is:
  - time comes in as `Millis`; `crates/m2-server-core/clippy.toml` forbids `Instant::now`, `SystemTime::now`, `thread::sleep`, `HashMap` and `HashSet`;
  - randomness only from the generators `Server::new` and `Server::with_content` are seeded with; the edge seeds them from the operating system, tests with a fixed seed. The world (monsters, damage) draws from its own stream (`world_rng`, stream 1), so monsters never shift the tickets of the snapshots;
  - game numbers (health, damage, experience) are checked or saturating integers; formulas with fractions work in whole thousandths, never floats;
  - no trigonometry or `hypot` in the core: directions come from the `DIRECTIONS` table and lengths from `walk::length` (an exactly rounded square root), so Windows and Linux give the same numbers;
  - storage only through `Effect::Store` and `Input::Stored`; the core never waits.
- **Exhaustive matches on `ClientMessage`**, without a `_ =>` arm, so a new message shows where it needs handling. Say in `session.md` what each does out of turn.
- **Every client byte is untrusted.** Check the stage before acting on a message, check names, slots, classes and kinds on the server, and close the connection on anything out of turn. A connection only ever sees its own account's characters, and only hears of the vids it sees (`random_sessions.rs` checks both). A hit is checked on the server (alive, seen, reach, rate); damage is worked out there, never taken from the client. Items likewise: a player handles only its own bag, every place, count, class, level, reach and owner is checked, gold is a checked number, and an item has one holder at a time (a bag, the ground, or gone); `random_sessions.rs` checks that no bag holds two items in one place. Moves too: each is checked from where the server has the mover at the move's time (held to at most 500 ms back), against the map's walls and reach, and a refused one puts the mover back. Shops and skills too: prices come from content, never from the client; gold and room are checked before anything changes; a skill must be learned, of the player's group, paid for and cooled down, and its hits fit its window, reach and counts.
- **No panics:** `unwrap`, `expect`, indexing and `panic!` are denied in `m2-server-core/src/`.
- **Secrets:** there are no passwords; tickets are kept in a `SecretBox` and compared in constant time. The TLS private key is never logged or printed (`Identity` shows only its pin), files are read with a size cap, and a key the server makes is written for its owner only. Providers' codes and PKCE verifiers stay in `SecretString` from the message to the token request; client secrets come from the environment; ID tokens are checked and dropped, never logged. Events, logs and telemetry name accounts and characters by number: never tickets, codes or chat text. Text a client sends for the logs (its build) is logged with control characters as `?`.
- **Facts and choices:** a rule follows Quantum Core X where it is right (facts in our own words, `docs/source-policy.md`) and is openm2's own where QCX is wrong or silent. `session.md` says which for each rule.
- **No Metin2 data in the server:** no Metin2 data in the code, the seeds or the tests (`docs/source-policy.md`, "Our own server"). Values from QCX's behaviour (start positions, class values) are config defaults, noted in `session.md`.
- **Dependencies:** both crates depend on `m2-protocol` and `m2-content` only (and the core); the client's crates only in tests (`ALLOWED_DEV_DEPS`).
- **Content only through `m2-content`:** the core takes a checked `Content` and uses its world-unit view (`groups()`, `npcs()`, `run_speed_cm()`, `shop()`) and works skills' formulas out with `Formula::eval` in thousandths; it never parses files.
- **Storage:**
  - SQL with bound parameters only; a dynamic identifier only in test setup (`AssertSqlSafe`, a schema name the test made).
  - A schema change is a new migration file; a released one is never edited.
  - A new storage rule goes into both stores and into `check_rules` in `tests/storage.rs`, which runs on both.
  - Saves carry the character's save count and storage keeps only a higher one; a login waits for its account's saves under way (`storage.md`). A new field of a character is saved the same way; its items, quickslots and skills are written with it, in its transaction, and a drop saves the dropper at once (`world.md`, "The ground").
  - The database URL comes only from `OPENM2_DATABASE_URL` and is never printed; errors are logged without it.
- **Tests:**
  - A new rule gets a scenario (or a line in one) and, if it touches the wire, a check with real clients.
  - Postgres tests read `OPENM2_TEST_DATABASE_URL`, make their own schema, drop it, and are skipped without it.
  - New or changed snapshot: `INSTA_UPDATE=always cargo test -p m2-server-core`, read the `.snap` diff line by line, and say in the handoff why it changed.
  - Sockets bind `127.0.0.1:0`; tests create accounts with `Cost::Test` hashing.
